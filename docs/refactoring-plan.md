# 架构优化计划

目标：统一业务接入边界，支持兼容任务恢复，隔离通道故障，降低模块与页面改造成本。沿用模块化代码库、PostgreSQL、独立 API/Worker 和 Astryx。

| 顺序 | 实施内容 | 验收 | 状态 |
| --- | --- | --- | --- |
| 1 | 统一 TaskService 的创建、输入/确认、取消、重试及查询；HTTP/邮件复用；邮件通过稳定任务通知协议读取 | 跨入口授权、幂等、取消及现有任务回归 | 完成 |
| 2 | 模块声明运行依赖；默认版本与历史版本分离；Worker 按模块版本/配置领取 | 模型变化不影响纯计算；不兼容 Worker 不抢领；历史版本恢复 | 完成 |
| 3 | 收取、通知与发送独立循环和锁；记录循环健康；故障不终止任务 Worker | 慢收信不阻塞发送；循环故障隔离；未知发送不重发 | 完成 |
| 4 | 模块生成命令与配置清单；按 Schema 生成表单；输入/结果组件扩展；拆分工作台 | 生成模块编译与执行；桌面/手机表单和自定义渲染 | 完成 |
| 5 | 轻量就绪检查、分类心跳、队列/邮件指标；可配置保留与安全归档 | 就绪不聚合业务报表；积压可观测；归档可重入且保留审计与幂等 | 完成 |

每阶段先完成实现及针对性验证，再进入下一阶段；收尾运行格式、文档、类型、lint、核心覆盖率、构建、浏览器及隔离 Compose 验收。邮箱默认关闭，保留已有数据库及凭据；历史迁移只追加。归档默认关闭，不自动删除用户数据；真实邮件与大规模容量不在本地隔离验收中冒充通过。

全部阶段已实现。验收：83 项后端测试、4 项桌面/手机浏览器流程、类型/lint/格式/文档/许可及构建通过；隔离 Compose 验证重启、运行权限、归档事件回放、备份与恢复。归档范围为执行事件和调用尝试，压缩保存在同一数据库，不自动销毁业务历史。
