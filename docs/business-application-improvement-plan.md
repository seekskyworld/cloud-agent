# 业务复用重构：范围与状态

本次复盘发现，原有框架已经具备持久任务、幂等、确认、身份授权、邮件投递、业务包与恢复能力。接入中另建一套业务执行状态，不足以证明框架缺少这些能力。因此将原先较宽的应用组件计划收敛为：打通现有机制的组合接口，提供明确的复用文档。

## 已写入源码

| 改动 | 复用的既有机制 | 新增边界 |
| --- | --- | --- |
| BusinessTransactions.run | Database.transaction、主体复核、任务租约 | 领域更新与发信登记使用同一短事务；拒绝旧 run 和维护期间写入 |
| BusinessMail.enqueue / 共用投递函数 | mail_outbox、发送锁、发送结果未知及管理恢复 | 业务策略、稳定请求键、原任务绑定、发送前复核 |
| 服务回执 | 收件去重、external_signals、外部等待消费 | 认证来源和持久请求匹配；服务主体独立审计，不冒充用户确认 |
| 端口工厂上下文 | 类型化 PortBinding、依赖装配及资源释放 | 可直接获取事务、身份、任务与已装配邮箱；可选异步工厂 |
| 可选公众入口 | BusinessInstance、API 宿主、静态前端构建 | 显式 publicReads 与网站清单；受保护 routes 保持原鉴权 |
| Cookie 认证适配 | IdentityProvider、当前主体查询、已有 Token/OIDC | 支持 HTTP 请求上下文和受保护 Cookie；不新增用户库 |
| 业务检查与恢复保护 | /ready、维护模式、联合恢复、正文退役 | 可贡献 ready/recovery 检查；业务邮件纳入保护与对账 |
| 接入说明和中立示例 | 公共 SDK、Tool.approval、持久任务与端口 | 按需求查找接口，不依赖代码生成器 |

完整调用方式、限制与升级说明见 [业务复用指南](business-reuse.md)。

## 保留在业务中的职责

商品、库存、订单、金额与回执正文解析属于领域实现。网页和邮件应向同一 TaskService 提交任务；确认与重试复用框架，领域工具在执行时重新校验资源版本并幂等提交。

邮箱验证码、公开注册、角色到业务能力的映射、外部服务具体授权及补偿条件不设默认业务规则。没有新增通用验证码数据库、第二套角色系统、第二套确认系统或新的消息投递状态机。

事务发件首期使用既有 PostgreSQL 和邮件通道，不承诺任意跨库原子提交，也不把每个外部协议都抽象成已经实现的发送适配器。未来其他渠道存在实际复用需求时，再根据其接受/拒绝/未知语义扩展。

## 验证状态

本轮遵循不运行测试的要求，仅进行源码审阅及类型、格式、文档和依赖方向等静态检查。静态检查结果见实际交付记录；不代表并发、数据库迁移、浏览器或真实邮件验收通过。

新增迁移 031 尚未应用到运行数据库；未部署、未发送真实邮件。兼容契约基线未改写。上线前仍须按 [开发约定](../AGENTS.md) 完成适用的数据库、SDK、邮件、页面和恢复验收。
